### 5.1. Создай пустую базу conferences

В этом основном способе мы создаём всё кнопками и формами phpMyAdmin. Вкладка «SQL» и готовый файл для импорта не нужны.

1. Открой phpMyAdmin по адресу из предыдущего шага и войди в свою локальную MySQL.
2. Нажми значок домика или логотип, чтобы перейти на уровень сервера.
3. Открой вкладку **«Базы данных»**. Другой вход в ту же форму — пункт **«Создать БД»** / **«Новая»** слева.
4. Найди блок **«Создать базу данных»**.
5. В поле имени введи **`conferences`** латиницей.
6. В списке сравнения/сопоставления выбери **`utf8mb4_unicode_ci`**.
7. Нажми **«Создать»**.
8. Слева нажми на появившуюся базу **`conferences`**.

**Проверка:** вверху страницы написано «База данных: conferences», а таблиц пока нет.

Если такая база уже существует с рабочими данными, её не нужно удалять. Для новой учебной попытки можно взять `conferences_study`, но затем именно это имя нужно указать и в `dbname` файла `db.php`.

### 5.2. Разберись, что вводится в форме столбцов

При создании таблицы phpMyAdmin покажет сетку: одна строка сетки — одно поле таблицы.

| Колонка формы | Что в ней задаём |
|---|---|
| **Имя** | Точное имя поля: например, `full_name` |
| **Тип** | `INT`, `VARCHAR`, `ENUM`, `DATETIME` или `TEXT` |
| **Длина/Значения** | Число для `VARCHAR`; список вариантов для `ENUM` |
| **По умолчанию** | Какое значение взять, если PHP не передаст поле |
| **Сравнение** | Для строк можно оставить наследование от таблицы |
| **Атрибуты** | У нужных целых чисел выберем `UNSIGNED` |
| **NULL** | Галочка разрешает отсутствие значения |
| **Индекс** | `PRIMARY`, `UNIQUE`, `INDEX` или отсутствие индекса |
| **A_I** | Галочка автоматической выдачи нового ID, то есть `AUTO_INCREMENT` |

Широкая форма может иметь горизонтальную прокрутку. Если справа не видно «Индекс» и «A_I», прокрути сетку вправо.

Дальше в таблицах инструкции:

- **«пусто»** означает оставить поле ввода пустым;
- **«Нет» для NULL** означает не ставить галочку;
- **«Нет» для A_I** также означает не ставить галочку;
- **«Нет» для индекса** означает выбрать `---` или вариант без индекса;
- **«Нет» для значения по умолчанию** означает выбрать «Нет» / `None`, а не написать слово «Нет» в текстовом поле.

Для `INT` длину можно оставить пустой. В старой MySQL после сохранения может отображаться `int(10) unsigned`, а в новой — `int unsigned`: это не препятствует работе сайта. Для `DATETIME` и `TEXT` длину также оставляем пустой.

### 5.3. Создай таблицу users из семи полей

1. Убедись, что открыта база **`conferences`**.
2. Открой её вкладку **«Структура»**.
3. Найди блок **«Создать таблицу»**.
4. В поле имени таблицы введи **`users`**.
5. В поле количества столбцов введи **`7`**.
6. Нажми **«Создать»** / **«Вперёд»**.
7. Заполни семь строк по таблице ниже.

| Имя | Тип | Длина/Значения | По умолчанию | Атрибуты | NULL | Индекс | A_I |
|---|---|---|---|---|---|---|---|
| `id` | `INT` | пусто | Нет | `UNSIGNED` | Нет | `PRIMARY` | Да |
| `login` | `VARCHAR` | `100` | Нет | пусто | Нет | `UNIQUE` | Нет |
| `password` | `VARCHAR` | `255` | Нет | пусто | Нет | Нет | Нет |
| `full_name` | `VARCHAR` | `200` | Нет | пусто | Нет | Нет | Нет |
| `phone` | `VARCHAR` | `15` | Нет | пусто | Нет | Нет | Нет |
| `email` | `VARCHAR` | `254` | Нет | пусто | Нет | `UNIQUE` | Нет |
| `role` | `ENUM` | `'user','admin'` | Как определено: `user` | пусто | Нет | Нет | Нет |

Особенно внимательно настрой три строки:

**Строка `id`:** в индексе выбери `PRIMARY`, в «A_I» поставь галочку. Если phpMyAdmin откроет окно подтверждения индекса, оставь только поле `id` и подтверди. Первичный ключ должен состоять из одного `id`.

**Строка `login`:** индекс `UNIQUE` создаётся отдельно для одного `login`. Не объединяй `id` и `login` в общий индекс. Если открылось окно, проверь, что в нём только `login`, и подтверди.

**Строка `email`:** выбери отдельный индекс `UNIQUE` только для `email`, аналогично `login`. Это требование из пояснений.

**Строка `role`:** сначала выбери тип `ENUM`. В «Длина/Значения» введи целиком:

```text
'user','admin'
```

Это два значения с обычными одинарными кавычками и запятой между ними. В «По умолчанию» выбери **«Как определено:»** / **«Определено пользователем»** / **`As defined:`**, затем в появившемся текстовом поле напиши:

```text
user
```

Для значения по умолчанию кавычки не нужны. Не выбирай `NULL` вместо `user`.

Внизу формы проверь настройки **таблицы**:

- **Тип таблицы / Движок / Storage engine:** `InnoDB`.
- **Сравнение:** `utf8mb4_unicode_ci`.

Нажми **«Сохранить»**. Это сохраняет всю таблицу, а не одну строку формы.

**Проверка:** открой `users` → «Структура». Видно семь полей, у `id` — первичный ключ и `AUTO_INCREMENT`, у `login` и `email` — отдельные уникальные индексы. Все поля имеют `NULL = Нет`, у `role` значение по умолчанию `user`.

### 5.4. Создай таблицу requests из восьми полей

1. Слева нажми именно на имя базы **`conferences`**, чтобы выйти из `users` на уровень базы.
2. На вкладке «Структура» найди создание таблицы.
3. Введи имя **`requests`** и количество столбцов **`8`**.
4. Нажми «Создать» / «Вперёд».
5. Заполни форму:

| Имя | Тип | Длина/Значения | По умолчанию | Атрибуты | NULL | Индекс | A_I |
|---|---|---|---|---|---|---|---|
| `id` | `INT` | пусто | Нет | `UNSIGNED` | Нет | `PRIMARY` | Да |
| `user_id` | `INT` | пусто | Нет | `UNSIGNED` | Нет | `INDEX` | Нет |
| `room` | `VARCHAR` | `200` | Нет | пусто | Нет | Нет | Нет |
| `starts_at` | `DATETIME` | пусто | Нет | пусто | Нет | Нет | Нет |
| `payment` | `ENUM` | см. список ниже | Нет | пусто | Нет | Нет | Нет |
| `status` | `ENUM` | см. список ниже | Как определено: `Новая` | пусто | Нет | Нет | Нет |
| `review` | `TEXT` | пусто | `NULL` | пусто | Да | Нет | Нет |
| `created_at` | `DATETIME` | пусто | `CURRENT_TIMESTAMP` | пусто | Нет | Нет | Нет |

Для **`payment`** в поле «Длина/Значения» введи одну строку:

```text
'При очном посещении','Переводом по системе СБП'
```

Для **`status`** в «Длина/Значения» введи:

```text
'Новая','Мероприятие назначено','Завершено'
```

Затем для `status` выбери в «По умолчанию» **«Как определено:»** и впиши **`Новая`** без кавычек. Буквы и пробелы в вариантах оплаты и статусов должны точно совпадать с этим примером и PHP-кодом.

Для **`review`** поставь галочку **NULL** и выбери **NULL** в значении по умолчанию. Сам текст `NULL` в поле отзыва вписывать не нужно. Пока отзыва нет, БД хранит отсутствие значения.

Для **`created_at`** в списке «По умолчанию» выбери **CURRENT_TIMESTAMP**: БД сама запишет время создания заявки. Не выбирай «Как определено» и не вводи эту запись как текст.

Для **`user_id`** нужен обычный **`INDEX`**, не `UNIQUE`: один пользователь может создать много заявок. Галочку A_I у `user_id` не ставь — его значение будет передавать PHP из сессии.

Внизу снова выбери **InnoDB** и **utf8mb4_unicode_ci**, затем нажми **«Сохранить»**.

**Проверка:** в базе две таблицы. В `requests` восемь полей, `id` — `PRIMARY` и `AUTO_INCREMENT`, `user_id` — `UNSIGNED` с обычным индексом. `NULL` разрешён только для `review`, по умолчанию `status` равен `Новая`.

### 5.5. Создай настоящую связь между таблицами

Теперь обе таблицы созданы, но обычный индекс у `user_id` сам по себе ещё не означает внешнего ключа.

1. Слева открой **`requests`**.
2. Открой **«Структура»**.
3. Найди действие **«Связи»** / **«Представление связей»** / **`Relation view`**. В зависимости от оформления оно находится под списком полей, в меню «Ещё» или рядом с действиями структуры.
4. В открывшейся форме найди блок **«Ограничения внешнего ключа»** / **`Foreign key constraints`**. Для проекта нужна именно связь InnoDB, которую контролирует MySQL.
5. В новой строке связи задай параметры:

| Параметр формы | Значение |
|---|---|
| Имя ограничения | `requests_user_id_fk` |
| Столбец текущей таблицы / Column | `user_id` |
| Ссылаемая база / Database | `conferences` |
| Ссылаемая таблица / Table | `users` |
| Ссылаемый столбец / Column | `id` |
| `ON DELETE` | `RESTRICT` |
| `ON UPDATE` | `RESTRICT` |

6. Нажми **«Сохранить»** в блоке связи.
7. Открой представление связей снова и проверь, что строка сохранилась.

Получилась связь **`requests.user_id` → `users.id`**. Теперь нельзя сохранить заявку с несуществующим владельцем. `RESTRICT` не позволяет удалить пользователя, пока на него ссылаются заявки.

Не создавай вторую такую же связь, если первая уже видна. Название ограничения может отличаться от автоматически созданного SQL-импортом; PHP не обращается к этому имени, для сайта важны поля и направление связи.

Если связь не сохраняется, проверь через «Структура»:

- обе таблицы имеют движок **InnoDB**;
- `users.id` и `requests.user_id` — оба **INT UNSIGNED**;
- `users.id` имеет **PRIMARY**;
- `requests.user_id` имеет **INDEX**;
- выбрана база с обеими таблицами;
- если уже есть заявки, у каждой есть существующий пользователь.

Работа связей InnoDB и форма `Relation view` описаны в [документации phpMyAdmin](https://docs.phpmyadmin.net/en/latest/relations.html#relation-view).

### 5.6. Добавь администратора через «Вставить»

Вход администратора нужен до написания страниц, поэтому создаём его прямо в таблице.

1. Слева открой **`users`**.
2. Нажми вкладку **«Вставить»** / **`Insert`**.
3. В первом блоке новой строки заполни **колонку «Значение»** по таблице ниже.
4. Если рядом с полем есть список **«Функция»**, оставь его пустым: ничего дополнительно вычислять для вставляемых значений не нужно.

| Поле | Что ввести в «Значение» |
|---|---|
| `id` | оставить пустым — номер выдаст AUTO_INCREMENT |
| `login` | `Conf2027` |
| `password` | весь хеш из блока ниже |
| `full_name` | `Администратор` |
| `phone` | `8(000)000-00-00` |
| `email` | `admin@example.test` |
| `role` | выбрать или ввести `admin` |

Хеш не нужно запоминать. Временно создай в папке сайта **`hash.php`**:

```php
<?php
echo password_hash('Demo77', PASSWORD_DEFAULT);
```

Открой файл по локальному адресу сайта, скопируй полученную строку целиком в поле **password**. Для примера старого маршрута: `http://localhost/conf/hash.php`, для шестого: `http://conf.local/hash.php`. В этом файле подключение к БД не требуется. После вставки администратора удали временный файл. Входить затем нужно с паролем **Demo77**, а не со строкой хеша.

В готовом `database.sql` уже находится правильный хеш этого пароля. Разные результаты `password_hash()` для одного пароля допустимы: проверка идёт через `password_verify()`.

**Не выбирай MD5, SHA1 или PASSWORD в колонке «Функция». Не вписывай обычный текст `Demo77` в столбец `password`.** У сайта проверка через `password_verify()`, она ожидает сохранённый хеш из `password_hash()`.

Если форма показывает два блока вставки сразу, заполни только первый. Второй оставь неиспользованным/с отметкой «Игнорировать», если она предусмотрена интерфейсом. Не создавай вторую пустую запись.

5. У заполненных текстовых полей не ставь галочки `NULL`.
6. Внизу нажми **«Вперёд»** / **«Вставить»** / **«Выполнить»** — подпись зависит от версии.
7. Открой **«Обзор»** таблицы `users`.

**Проверка:** есть одна строка с логином `Conf2027` и ролью `admin`. Столбец `password` содержит длинную строку, начинающуюся с `$2y$`. Номер `id` заполнен автоматически. Удачное выполнение вставки подтверждено сообщением phpMyAdmin.

Если видишь ошибку повторного логина, сначала проверь «Обзор»: возможно, администратор уже создан. Повторно добавлять его не требуется.

### 5.7. Проверь результат через интерфейс

1. Слева выбери базу **`conferences`** → **«Структура»**.
2. Должны быть ровно две прикладные таблицы: **`users`** и **`requests`**.
3. Открой `users` → «Структура»: семь полей и индексы `PRIMARY(id)`, `UNIQUE(login)` и `UNIQUE(email)`.
4. Открой `requests` → «Структура»: восемь полей, `PRIMARY(id)`, индекс `user_id`, у `status` по умолчанию `Новая`, у `review` разрешён `NULL`.
5. Открой `requests` → «Связи»: видна ссылка `user_id` на `users.id`.
6. Открой `users` → «Обзор»: администратор существует.
7. Открой `requests` → «Обзор»: пока ноль записей. Первую заявку позже создаст сам сайт.

Отдельная служебная база phpMyAdmin, если она есть, не считается третьей таблицей портала. Наши прикладные таблицы находятся внутри `conferences`.

Если обнаружил ошибку в поле, нажми **«Изменить»** в его строке на вкладке «Структура», исправь конкретную настройку и сохрани. Например, включи забытый `UNSIGNED` или поправь значение по умолчанию. Если поле участвует в связи, MySQL может потребовать сначала изменить ограничение — поэтому удобнее сверить типы до создания связи.

### 5.8. Сохрани результат в database.sql через «Экспорт»

База уже создана через формы. Теперь получим SQL-файл для переноса и сдачи задания.

1. Слева выбери именно базу **`conferences`**, а не отдельную таблицу.
2. Открой вкладку **«Экспорт»**.
3. Выбери способ **«Обычный — отображать все возможные настройки»** / **`Custom`**, если нужно сохранить создание самой базы.
4. Убедись, что выбраны **обе** таблицы: `users` и `requests`.
5. Формат — **SQL**.
6. Для таблиц выбери экспорт **структуры и данных**, чтобы сохранилась и учётная запись администратора.
7. В параметрах создания объектов включи **добавление CREATE DATABASE / USE** (подпись может быть «Добавить выражение CREATE DATABASE / USE»).
8. Вывод выбери **«Сохранить вывод в файл»**, кодировку — **UTF-8**, сжатие можно оставить **«Нет»**.
9. Нажми **«Экспорт»** / **«Вперёд»**.
10. Сохрани полученный файл под именем **`database.sql`** в рабочей папке проекта.

Для основного маршрута шестой версии файл сохраняется рядом с папкой `public`:

```text
C:\OSPanel\home\conf.local\database.sql
```

Для пятой версии сохраняй в папку своего проекта. Проверь, что имя не превратилось в `database.sql.txt`.

Если в твоей версии выбран быстрый экспорт без `CREATE DATABASE / USE`, перед будущим импортом такого файла нужно будет сначала создать пустую базу и выбрать её. Вариант с отмеченным созданием базы удобнее для переноса с нуля.

Открой экспорт в редакторе и проверь, что там есть описания **обеих** таблиц, внешний ключ и вставка строки `Conf2027`. Порядок строк, комментарии, название внешнего ключа и служебные настройки в экспорте могут отличаться от короткого SQL-примера, но смысл структуры должен совпадать.

**Итог:** ты создал БД, поля, индексы, связь и администратора через интерфейс phpMyAdmin, а затем экспортировал результат. SQL вручную для этих действий писать не потребовалось.
